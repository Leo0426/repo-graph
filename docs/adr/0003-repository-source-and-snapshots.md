# 仓库归属、源码版本和发布快照独立标识

现有项目按本地目录或托管归档建立可更新的索引，并能通过项目定位源码。团队可能从同一远端接入多个分支，也可能在最新生成失败后继续使用旧 Wiki。建议分别标识仓库来源、带权限的仓库资源、生成任务和已发布知识快照，以便同一仓库在归属变化、重试和历史读取中仍能追溯到实际源码。

## 决策

- 保留本地目录和托管归档的接入方式。远端仓库通过连接适配器接入，使用规范的远端地址、实例边界和实例内稳定仓库标识确认来源。地址同名、远端编号重复或端口不同的实例保持隔离。归档上传产生可复用的受控对象，按实际格式、路径、条目和解压预算校验。显示名称可修改，始终用实际对象身份和摘要区分内容。
- 启动生成任务时冻结授权的仓库资源、精确源码版本和影响结果的生成配置。远端分支先解析为提交，归档固定到具体对象，本地目录如需版本化则使用能够复核的内容快照。相同输入的重复请求按同一资源和请求身份决定复用或重试。重试沿用冻结输入，拉取新分支头或采用新配置时创建新任务。源版本、发布版本和文档修订各自保有独立身份。
- 仓库详情同时展示在途状态和当前可读快照。完成校验后才切换当前发布版本，正在执行、暂停、取消或失败的任务保留其历史状态。旧的有效发布保持可读，明确版本的来源、图谱、Wiki、引用与导出都解析到同一快照。历史删除、恢复和回收按资源权限与引用关系执行，仓库与空间的关联遵守 [资源授权决策](0002-resource-authorization.md)。
- 连接测试只读。凭据按连接隔离，轮换和停用有审计，诊断隐藏密钥。启用自动更新时，校验外部事件的身份、仓库对象和跟踪分支，再让事件、周期检查与手工提交共享幂等派发守卫。同一目标的重复触发只创建一个有效任务，失败或取消后可由人工显式重试。停用或移除连接停止新同步，已创建任务仅在权限和凭据有效时按冻结输入执行，发布历史仍可按授权读取。重连须确认同一实例与同一仓库后才恢复旧绑定。

## 权衡

只保存分支当前状态可以降低存储成本，但任务重试会受分支变化影响，历史引用也可能指向不同的代码。冻结源码与发布快照提高了复现性，增加了版本保留、验证和清理成本。首批使用现有本地索引管道和仓库列表扩展版本读取，按部署需求启用远端连接和自动同步。尚未冻结的现有索引继续按当前索引读取，历史快照能力从能够提供完整来源证据的任务开始。

## 验收边界

用两个同名远端、并发导入、可重复提交的归档及两个源码版本核对隔离、去重和版本固定。最新任务失败或连接停用后，旧快照仍按授权解析原源码及引用。重复事件与手工请求同时到达时只派发一次，错误远端或过期绑定不借用其他连接凭据。物理回收前验证待恢复任务、发布版本和其他授权资源引用。

## 远端 Git 运行配置

- 服务需要可执行的 `git`。`REPOGRAPH_GIT_ORIGINS` 接受逗号分隔的完整源地址，例如 `https://git.example.com:8443`。通过 HTTPS 连接仓库，本地回环测试可使用显式配置的 HTTP 地址。工作台从关联仓库入口新建或复用 Git 连接。
- 凭据保存在加密存储中。默认密钥文件名为数据库路径加 `-git-key`。部署可用 `REPOGRAPH_GIT_ENCRYPTION_KEY` 提供 Base64 编码的 32 字节密钥。迁移存储时保留原密钥。
- 签名事件向 `POST /api/v1/git/events/{connectionId}` 发送 JSON，包含 `url`、`ref`、`commit` 和 ISO 8601 格式的 `timestamp`。`X-Git-Event-Signature` 使用 `sha256=` 前缀和原始请求体 HMAC-SHA256 的小写十六进制摘要。连接设置保存签名密钥，仓库设置启用事件、周期检查和同步后自动发布 Wiki。
- 工作台的「托管平台」可以选择 GitHub 或 GitLab。连接通过平台元数据 API 核对克隆地址，登记平台、实例源地址和实例内仓库 ID。GitHub.com 使用固定的官方 API 域名，企业实例使用原实例的 `/api/v3`，GitLab 使用原实例的 `/api/v4`。查找暂停在重定向处，管理员需提供当前规范地址。私有仓库需提供可读取元数据和 Git 内容的连接令牌。[GitHub 仓库 API](https://docs.github.com/en/rest/repos/repos#get-a-repository)、[GitHub Enterprise Server 仓库 API](https://docs.github.com/en/enterprise-server@3.22/rest/repos/repos#get-a-repository)、[GitLab 项目 API](https://docs.gitlab.com/api/projects/)。
- 改名或调整项目路径后，通过连接设置中的「验证并重连」更新地址。仅同一实例及同一仓库 ID 能沿用连接、跟踪分支、加密凭据和发布历史。通用 Git 连接沿用地址身份。迁移前可在当前路径上补验托管身份，保留已有仓库 ID。HTTP 客户端可调用 `POST /api/v1/git/connections/{connectionId}/reconnect`，提交 `revision`、`url`，首验时还需提交 `adapter`，并可提交 `enabled` 或替换凭据。
- 管理员可断开连接并清除令牌和事件密钥。该操作停止新同步，保留跟踪关系和已发布历史。HTTP 客户端可用 `DELETE /api/v1/git/connections/{connectionId}?revision=...`。重新启用托管连接会重新核验平台仓库 ID。
- Git 快照的 `source.gitCommit` 是解析并验证后的提交 SHA。托管连接在测试分支、同步解析、工作器检出前后均核对上游仓库身份。检出保留普通 Git 对象的原始内容，符号链接、子模块和 LFS 托管对象保持各自的来源边界。

## 归档原件与回收

- 新导入的归档原件按压缩文件的 SHA-256 存储。多个授权仓库可以引用同一原件，各自保有项目身份、显示名称、索引及权限。导入和从现有资产复用均接受 `Idempotency-Key`。工作台的归档资料页可更改显示名称或将原件复用到另一个仓库。
- 归档发布快照冻结对象 ID 和 SHA-256，并核对已索引文件的摘要是否与原件清单一致。旧归档如果只保留了解压结果，历史索引仍可使用，复用原件需要重新导入。
- 原件无引用后按 `REPOGRAPH_ARCHIVE_RETENTION_SECONDS` 保留，默认 86400 秒。物理清理检查资产、在途导入和快照引用。引用仍存在时，归档的永久删除会返回冲突。

## 发布快照的退役和恢复

- 仓库管理员可在 Wiki 的「管理快照」中退役或恢复已发布快照。正常读取会跳过退役版本。退役当前版本后，正常入口会读取仍可见的最新版本。恢复沿用原快照和正文修订。
- `REPOGRAPH_SNAPSHOT_RETENTION_SECONDS` 设置退役保留期，默认七天。到期后，只有没有下游快照、空间固定关联、待审批草案或有效问答引用的版本才可回收。清理保留任务历史。在仍有引用时，仓库管理员可恢复版本，再处理草案或关联。

## 仓库回收站

仓库管理员可在仓库列表的操作菜单将本地、归档或 Git 仓库移入回收站。普通入口随即撤出仓库和历史引用。已排队或暂停的仓库任务保留原记录并停止派发，运行中或尚在收尾的任务需先结束。恢复沿用原仓库 ID、版本、空间关联和任务记录。旧的索引删除与归档删除接口保留原响应形状，并执行移入回收站。

`REPOGRAPH_PROJECT_RETENTION_SECONDS` 默认七天。保留期后可显式请求永久清理，系统检查待恢复的任务、空间关联、待审批草案、Git 发布以及有效问答引用。存在依赖时可先恢复仓库处理这些引用。永久清理移除仓库的索引和自有快照，保留本地源码目录。托管归档和 Git 副本通过持久回执异步清理，失败后可重试，其他仓库仍引用的归档原件继续保留。清理后的本地目录重新接入会分配新仓库 ID。
