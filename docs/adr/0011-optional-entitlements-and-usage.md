# 将托管权益、任务配额和用量作为独立政策

本地部署已经有授权、模型配置和生成预算。托管场景可能要求组织开关、试用、资金和用量对账。若把余额或试用状态并入资源角色，会让暂时的额度服务故障影响历史知识读取，也会让组织权限难以独立审计。

## 决策

- 单机继续使用现有的管理员配置和预算。在确有托管需求的部署中加装权益适配器，分别判断部署许可、组织功能开关、任务准入、物理模型调用资格及用量。资源可见性由 [资源授权](0002-resource-authorization.md) 独立判定。授权主体、策略及用量记录均带稳定组织身份。
- 外部权益按组织发布完整、版本化快照，短暂故障时仅在允许的陈旧期和权益有效期内使用上一份完整快照。活动批次包含开始时刻，到结束时刻失效。批次重叠时按最早到期顺序消费，同刻按稳定标识排序。权益不可确认时，相关的新准入暂停并给出可诊断状态。许可过期和权限撤销分别处理，健康状态和治理入口遵循各自的部署策略。
- 创建新任务与额度记账同事务，同一请求重放和原任务重试复用已记账结果。失败、取消和逻辑删除保留历史。只有政策允许且确认物理清理的记录才能冲销，冲销幂等。额度调整保留真实用量，查询区分已核实数据和未知数据。
- 模型身份、投递资格和记账归属由服务端确定。模型实际发送前重查有效资格，等待和重试均核验，已发送的请求可在原时限内收尾。运行和尝试记录区分试用次数耗尽、余额不足、上游限流、凭据拒绝、网络失败以及未知费用，结算按实际发送与用量证据核对。用量细节只向获准的管理范围披露。

## 取舍

给各入口单独计费容易实施，但重复触发、恢复和外部续期会产生不一致。持久化准入与异步结算增加状态协调工作，换取精确计次、真实对账和可解释的故障。仅在需要托管策略的部署开启。

## 验收

并发耗尽同一批次时准入次数与记账一致。验证时间边界、批次重叠、缓存超期、途中组织停用、多次重试及重复冲销。权益不可用时返回未知状态，历史运行与文档继续按当前访问权限判定。

## 托管准入和台账

使用 `REPOGRAPH_HOSTED_ENTITLEMENTS=1` 启用组织仓库的托管政策。管理员可通过 `PUT /api/v1/admin/entitlements/{organizationId}` 接收外部系统发布的完整快照。快照通过递增版本及有效期校验，重复投递同一版本返回同一结果。缓存有效期取快照到期时间和部署配置允许的最长陈旧期。治理和历史读取仍依照原权限。

仓库任务、Git 同步和限定于同一组织的问答轮次在创建时扣减任务配额。重放和已记账的 Git 重试复用原记录。模型发送在同一事务领取调用许可并写入实际发送记账，随后按供应方提供的字段结算。没有计量凭证的费用显示未知。管理员仅在政策允许且受管归档或 Git 检出确认清理后可冲销任务。冲销保留原记录和实际模型用量。

试用额度耗尽后可以消费当前有效的按量批次。按量批次的任务与模型配额分别计数，模型发送仍须满足独立的余额和资格检查。历史查询保留实际使用的批次和计费模式。

管理员可为同一组织下已经发送的调用补录上游用量凭证。凭证可补齐未知的输入、输出或费用，原已知值与运行终态保留。相同凭证可安全重放，冲突或跨组织记录会被拒绝。供方没有给出的字段继续显示未知。
