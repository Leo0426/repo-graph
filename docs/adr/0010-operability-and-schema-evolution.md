# 用权威记录支撑恢复与渐进升级

现有服务以本地数据库与托管文件运行。引入历史快照、后台作业、共享文档和外部执行后，需要确保重启、部署升级和清理均可恢复业务状态。

## 决策

- 初版继续单节点。事务存储持有身份、归属、版本指针、队列、审计与用量。源码快照、文件原件和已验收产物由持久文件存储按版本保存。向量、全文检索、图缓存和展示投影从有版本的输入生成，重新创建时校验模型、内容和版本身份。
- 当文件与记录跨事务时，先落持久候选，再提交权威引用。发布、清理、导出和事件投递需要可重试回执。逻辑删除即时撤销可见性，物理回收经保留期、活动尝试和引用检查。失败回收可续做，对仍在运行或被引用的版本保留数据。
- 区分存活、可服务、功能可用和降级，按实际存储、索引、执行器和模型状态发布能力。管理员按权限看队列积压、进度、失败阶段和额度，能用请求、任务或运行 ID 关联脱敏诊断。指标和外部事件传递异步限幅，分别记录任务受理与终态。配置修订先校验，再作为整体切换；在途任务沿用既有版本。
- 升级按扩展结构、兼容读取、迁移核对、逐步启用新写入的顺序开展。迁移可重复执行，补齐缺失关系，保留已进行的归属或撤权修改。历史身份或版本无法确认时标记例外，交由管理员复核。回退到仍能读已写数据的版本。收缩结构前验证保留、回滚及读写方兼容。
- 备份同时覆盖事务数据、原件、发布产物与密钥。先在独立环境恢复并核查历史读链和任务仲裁。若单机资源成为瓶颈，再拆独立执行器或迁移存储，并核对存储权威、幂等和租约语义。

## 取舍

全面拆分存储能独立扩展吞吐，但在现有规模下会提高部署与恢复成本。保持单节点允许先验证领域边界，同时需要应对文件与数据库之间的中断，并通过资源隔离保护查询可用性。

## 验收

用全新库、旧版本样本及迁移中途退出三种场景验证启动、重跑和回退。重启后可读取旧版本引用，已发布结果及已计用量保持一致。模拟存储、索引和执行器单项不可用，诊断显示真实降级范围；后台清理失败可重试。

仓库永久清理先提交数据库清理和托管文件回执，再处理磁盘上的归档或 Git 副本。服务重启会继续处理待清理记录。回执保存终态，CLI 与工作台可以重新查询；从清理失败的回执继续执行时，仍校验物理目录的归属和实际路径。

HTTP 指标在内存中按分钟汇总，由后台限量写入 SQLite。管理员可读取最近 30 天的逐小时计数与延迟。202 受理与其后可查询的任务终态分开。存储暂不可写时保留有界缓冲，恢复后重试。运行和恢复检查见 [服务检查和故障定位](../operations.md)。
