# 由控制面持久化任务并授权执行

当前扫描已保存任务历史、执行尝试和成功的工具结果，重启时会识别中断，并支持显式重试。Wiki 有阶段缓存，Agent 有运行和步骤记录。提议以现有单机存储承载任务认领、恢复和结果接收。首版由本地执行器履约，后续可接独立执行器，继续使用同一组状态和授权约束。

## 任务、调度与恢复

- 任务绑定项目和明确的输入版本，接纳执行时冻结影响结果的模型策略、工具版本、配置和预算。一次任务可有多次执行尝试。分别记录用户可见状态和尝试的派发状态，使「已认领未启动」「运行中」「停止中」都可核对。在同一授权范围内重放相同请求复用任务身份，有相同幂等标识的不同输入须返回冲突。
- 控制面事务认领任务，以有期限的租约和单调递增的尝试序号限定执行权。提交进度、检查点或终态时，服务端核对当前尝试及其租约。失租后停止执行，迟到的续约不得恢复写入权。结果提交按内容摘要幂等，确认丢失时可重查。同一尝试再次提交不同结果视为冲突。控制面只接收通过校验的产物，知识快照发布遵循 ADR 0005。
- 检查点按已验证的阶段或工作单元保存，重试继续消费原任务剩余预算。重试耗尽的任务保留终态、失败原因及可审查的检查点，等待人工处置。用户暂停保留检查点并抑制自动续跑，取消不再接受新阶段和结果，待进程完成收尾后释放执行容量。重启时对账任务、租约和执行实例。确认已退出或可以隔离旧实例后才补派。无法确认时保留待对账状态，避免重复执行及重复外部调用。
- 即时请求、预约和来源事件统一入队。重复事件按来源和目标版本归并。预约派发前复核当前资源权限、来源和容量。一次预约与周期规则保持独立，周期规则按指定时区计算。调度限制全局、资源范围和任务种类的并发。仅在后台任务挤压交互时启用保留容量，避免长任务占满问答等交互入口。可按模型池配置运行窗口，窗口关闭时停止接收新工作，为已运行单元提供有界的收尾时间并保存检查点。管理侧的改序、暂停及恢复通过预期修订号防止覆盖其他人的操作。

## 执行隔离与容量

- 执行器只领取自身已经探测可用且符合输入版本的任务类型。只读检索、常规生成、静态检查和需要执行项目代码的验证采用不同权限。只读能力可以独立履约。项目代码执行仅在具备隔离能力且明确启用时接受，使用只读源码和独立可写工作区，约束网络、凭据、CPU、内存、进程数、输出和时间。探测失败时明确标记不可用。产物经控制面校验后再交付上层审核或发布。
- 模型调用独立核算，区分任务槽位、模型池并发和单次请求期限。一次实际发送占用一个许可，每次重试重新准入并计入任务总预算。响应关闭或取消后幂等释放本地许可，上游用量以实际回执结算。限流和暂时不可用按有限退避处理，确定的授权或参数错误直接终止。记录可用的用量及阶段归属，无法确认的用量保持未知。团队权益和额度政策见 ADR 0011。
- 内部协议随任务冻结输入和结果版本，发布新版本前先加入可兼容的读取，再按执行器实际能力开放新任务。暂停新版本准入后，已有任务仍须可以读取和恢复。维护时先停止认领，等待在途任务退出或按规则保留检查点。提供脱敏的任务、尝试、阶段、耗时、限流与终态记录，区分进程存活、可接任务和等待对账。

## 权衡与验收

沿用现有扫描、索引和 Agent 的对外历史和状态语义，逐类迁入。内存队列接入简单，但丢失进程后无法判断认领归属。首版引入独立队列和运行集群会增加持久状态对账与本地部署成本。单机事务能先建立可恢复的接纳和发布语义，独立执行器在任务隔离或容量确有需要时接入。

使用合成任务验证双重认领、认领后未启动、续约迟到、完成回执丢失和旧尝试提交竞态。验证恢复只重跑未确认单元，人工暂停优先于窗口自动续跑，失效执行器无法发布，暂不可用与零结果可区分，并在实际隔离环境验证取消、超时、资源回收和无凭据外泄。

## Git 周期检查

Git 跟踪设置支持固定分钟间隔或按当地时区和星期检查。当地时间规则使用 IANA 时区，例如 `Asia/Shanghai`。夏令时切换时，重复出现的当地时刻只取第一次，缺失的当地时刻跳过该日。服务恢复后，已到期的周期检查合并为一次同步检查。固定间隔仍按分钟计算，签名事件可独立启用。

`PUT /api/v1/git/repositories/{projectId}/automation` 用预期 `revision` 更新规则。当地时间规则提供 `calendar.timeZone`、`calendar.localTime` 和可选的 `calendar.weekdays`，并将 `intervalMinutes` 设为 `null`。星期日为 `0`，星期六为 `6`。工作台按所选时区显示下次检查时间。

## 模型调用许可和后台时段

管理员可为每个模型配置档案设定物理调用并发上限和问答保留数。默认并发上限为四，问答保留数为零。服务在写入模型调用台账时原子核对全局和档案容量、档案启用状态及当前凭据。任务继续使用冻结的模型和生成参数。轮换或清除凭据后，使用旧凭据的后续调用会返回明确状态。正在执行的请求在原有时限内结算。容量拒绝不会写入已发送用量。

可选的 `pool.backgroundWindow` 使用 `timeZone`、`weekdays`、`start` 和 `end`。星期按窗口起始日期计算，跨午夜时延续到次日，结束时刻不包含在窗口内。夏令时重复的当地时间按同一规则判断。Wiki 在关闭的时段保留排队和阶段检查点。已开始的阶段按原期限完成，下一次模型调用等待窗口开放。人工暂停需显式恢复。问答仍按实时并发和保留数准入。

持久问答、新版 Wiki 和变更评审在明确的 HTTP 429 或 503 响应后可以退避并重试一次。退避受总期限与预算限制，重试前复查授权和租约，重新申请物理调用许可并单独记账。明确拒绝与没有确认响应的调用保留原状态。

## 独立验证执行器

可选 `node-test-v1` 在本机 Docker 的独立容器内运行显式选择的测试文件。输入仅复制发布快照中的字节，配置必须固定到容器镜像摘要。预检用合成内容确认根文件系统及源码只读、不可访问非回环网卡、临时目录可写，以及容器内没有应用访问令牌。传递给容器的环境与应用相互独立。进程有内存、CPU、进程数、输出和时限约束。[Docker 运行配置](https://docs.docker.com/reference/cli/docker/container/run/)、[无网络驱动](https://docs.docker.com/engine/network/drivers/none/)。

控制面保存任务和每次执行的租约。授权和快照在准备、启动、运行中及结果入库前重查。失租后按尝试身份确认容器退出，并清理本地暂存，再在原预算内尝试重派。无法确认物理退出时保留待对账。通过、测试失败、超时及取消分别记录。启用状态按当前探测结果声明，现有回执可按原权限继续读取。

## 模型变更评审

`submit_change_review` 将已有报告、模型配置和总预算一起入队，幂等重放沿用同一运行。每个完成的评审单元都有持久检查点，物理请求前记录已消耗的调用数和输入预算。应用重启后确认旧租约和在途模型许可到期，再从第一个未完成的单元恢复。恢复沿用原模型档案和剩余预算。暂停、取消及重新派发按运行修订控制，诊断展示该执行器的可用状态。

静态发现分诊入队时固定基线、源码上下文和模型档案。各项模型建议分别保存，审批报告与任务完成在同一事务提交。重启时已发送但缺少完成回执的建议标明结果未知，剩余发现继续使用固定上下文。

归档扫描任务固定存档身份、精确文件清单、工具配置指纹和总预算。执行在单独的暂存目录内读取校验后字节，逐工具保存回执。每个子进程组在启动前登记。重启后只有确认旧进程组退出并清理其目录，才继续未完成工具。退出无法确认时，诊断和任务执行状态显示待对账。任务仍沿用旧版扫描历史和显式重试入口。

## 本地整仓索引

`POST /api/v1/index/project` 受理后返回 `agentRunId`。执行使用提交时保存在受管暂存目录的源码、筛选条件和构建配置，单次最多暂存 1 GiB。重启后按已验收的文件检查点恢复。物理嵌入请求在发送前登记，恢复时等待旧请求期限届满再继续。诊断会标明在途请求产生的等待。进度仍可通过原索引状态接口查询，执行状态与尝试记录使用通用运行接口。
