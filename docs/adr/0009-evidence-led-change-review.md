# 用冻结变更证据驱动评审与人工处置

现有变更评审保存调用方提交的差异和基于当前索引整理的证据。已有 Agent 产生辅助建议，审核流程掌握最终处置。接入固定 Git 版本、本地未提交改动或多仓库评审时，评审范围、发布位置和人工决定需要分别保存。

## 决策

- 评审使用已验证的基线、目标和差异。仅有调用方差异时保留原有入口，并标记版本验证程度。增量以同范围内可验证的上次评审点为基准，基准不可用时回退到完整比较并记录原因。未提交文件可用受控覆盖层参与，固定已提交基线。多仓评审分别授权、比较和定位，背景仓库只提供上下文。
- 评审计划按变更规模、风险和预算拆分，保留范围、检查执行状态和未覆盖原因。静态检查与模型评审分别保留来源，检查报告区分实际零发现、未适用、不可用、失败和部分完成。离线依赖检查固定输入版本与公告快照。仓库画像、代码图、规则及检查缓存依据仓库、版本和工具指纹复用。
- 结构化发现是报告和行注释的共同依据。发现至少记录来源、版本、文件、位置及支持证据。审阅范围与可发布行范围分别校验，旧位置或差异外发现可在报告中保留。重名、重命名和跨仓引用按实际仓库与版本解析。覆盖不足或裁决不可用时保留可核查证据和未完成状态。
- 解释、针对报告的追问和人工申诉引用原评审版本。证据不可用时单独出结果。复核可提出重新分类或撤回建议，采纳、抑制以及规则发布继续走已有人工流程及审计。历史修订、误报和确认反馈可归纳为候选规则，发布前通过审查和回归验证。变更说明复用冻结报告，可用确定性的内容作为生成降级路径。
- 可选修订建议以固定版本为基线，交付可审查的补丁及实际验证状态。验证使用 [隔离执行边界](0006-durable-jobs-and-worker-boundary.md) 下获准的验证能力。采纳由具备写权限的操作者显式触发，由服务端复查目标版本和保护范围。若评审期间源分支推进，新版进入独立评审或被明确纳入新的冻结范围，发布记录只声称已覆盖的版本。

## 取舍

以模型文本直接作为交付物，较难核对覆盖和回放历史。结构化事实、报告与人工处置分离增加存储和校验步骤，但支持精确追溯、重复导出和一致复核。首批扩展可复用已有变更快照，依次接入验证版本、确定性检查与可选模型辅助。

## 验收

覆盖过期基线回退、重命名、两个仓库同路径、评审中新提交、工具断开和模型超时。检查结果及行注释能定位到实际版本，未覆盖与零发现可区分。重复复核保留历史，规则候选与补丁获得人工采纳前保持待审，新版漂移提示冲突。

评测固定合成仓库、版本、模型配置、规则及工具版本。用脱敏的响应夹具复现执行分支，结合人工确认的样本评估发现质量、引用准确性、覆盖及预算。

## 已发布版本比较

工作台「变更评审」可选两个同仓库的已发布快照。省略基线时使用最近一次已验证评审的目标版本，基线不存在或已退役时比较完整目标并记录回退原因。评审按快照中的源码计算差异，源码和代码图证据固定到目标快照。报告、导出和模型运行每次读取时重新校验两个快照的可见性。

服务通过 `POST /api/v1/change-reviews/compare` 接收请求，CLI 和 stdio MCP 提供 `compare_change_snapshots`。同一主体用同一幂等键重放得到同一份评审，包括自动选择的基线。手动粘贴差异继续标记为未经版本验证。

## 组合范围和检查回执

`compare_change_scope` 一次接收最多四个目标仓库和四个背景仓库。每个目标独立选择基线并生成报告，背景只返回固定快照内显式选择的行段。组合报告每次读取时复核全部仓库与快照，单仓报告仍独立按原范围授权。

外部扫描导入保留声明版本、原检查格式、规范化发现和回执摘要。冻结评审按目标版本读取相关回执，区分零发现、未适用、不可用、失败和部分完成。相同工具版本的后续导入只影响以后生成的评审。外部回执将来源标记为报告声明的版本。

受管归档扫描核对归档文件摘要，在任务租约内保存版本化工具回执。评审该归档发布版时标记来源为已核验归档源码，发现定位到同一版本的文件和行。导入的报告仍保留声明版本标签。

完整索引或显式重新索引支持的依赖清单时，程序记录读取到的清单摘要和 Maven 公告目录摘要，并进行离线版本比较。发布时把回执固定到知识快照。评审从目标快照读取回执，因此后续修改工作副本或公告库不会改变旧报告。其他生态、无法核对的版本和达到扫描上限都有独立覆盖状态。

## 结构化发现和人工处置

每项发现保留所属仓库、目标快照、来源、文件、位置及差异证据。报告区分可定位到变更行的发现和仅留在报告中的发现。编辑者可在工作台确认、驳回、请求复核或对已处置的发现提出申诉。每次操作核对原报告、现有权限和修订号，以幂等回执追加历史。

工作台可从整份报告或一项结构化发现建立私有问答。会话只从固定报告提取原有检查状态、位置和脱敏片段。追问的引用能回到同一报告及对应发现，历史读取继续检查原报告与快照权限。

管理员可将同仓、同工具规则的已确认或已驳回发现登记为规则候选的依据。候选记录具体报告、目标版本和人工处置修订。注册候选时明确提交规则文本与合成样本。发布仍通过原有审查及正反样本回归，并在提交事务中重新核对所引用的决策。申诉或快照撤权会使对应候选停止发布。

## 工作副本与补丁

`compare_working_copy` 接收普通本地 Git 仓库中最多 24 条明确选择的路径。服务用当前提交的原始对象核对已发布基线，再保存允许范围内的文件字节和变更。报告保留固定提交、捕获摘要及源码行坐标。覆盖层使用本地文件解析结果提供证据，代码图覆盖单独标为不可用。

编辑者可以用 `propose_change_patch` 为已发布评审目标中的受控文件提交完整替换文本及基础摘要。候选保存脱敏预览和可供 Git 检查的原始补丁。`submit_isolated_verification` 可显式选择候选，在固定快照的独立容器内覆盖选中文件。回执绑定候选及原目标快照。

`decide_change_patch` 需要人工提交修订号、幂等键及可选的通过回执。采纳时复核最新发布目标及被修改文件的字节。结果为可下载的已采纳补丁，操作者可据此自行应用到目标工作副本。目标已变化时保留待审记录并返回冲突。
