# 项目空间引用仓库，知识文档按不可变版本保存

现有项目按个人或组织归属提供源码索引，仓库 Wiki 保留生成历史和 Markdown 导出。旧 Wiki 引用携带生成时的路径和行号，但打开时定位的是当前索引。团队共享资料、编辑 Wiki 或复查历史引用时，需要固定每次读取实际使用的版本。拟将项目空间、仓库来源与文档版本建成独立身份，便于共享同一份知识，同时独立管理访问和保留期。

## 空间和资料归属

- 项目空间承载成员、目录和空间文档。创建空间时一并设立所有者，归档后按权限只读，删除后从正常列表和检索中移除。空间通过受限关联使用已有仓库资源和约定的来源范围。建立、解除和恢复关联均校验空间和仓库两侧的权限。来源有歧义时必须明确选择。解除关联立即从空间导航和查询中撤出该来源，独立的仓库授权继续有效。
- 空间共享文档、个人会话附件和仓库生成附件各有自己的归属和可见范围。目录位置和显示名称可变，文件身份与版本引用保持稳定。同目录同名时由调用者明确选择另存或创建新版，服务端重新验证目标目录、范围和基础版本。每个空间可限制关联仓库数、单文件大小和总占用。下调配额只限制新增，待清理的历史版本与回收站对象继续计入占用。
- 删除目录或文件时记录删除批次和原位置。恢复按该批次中的有效对象执行，原目录已不存在时可恢复到根目录，发生同名冲突时要求明确名称。永久清理成功后释放占用。清理和解析任务均凭具体对象版本与操作批次写入，以免晚到的任务影响已恢复或重新上传的版本。

## 文档生效与导出

- 保存时追加不可变文档版本并记录当前版本。Markdown 支持空文档与长文的完整源文读写，保留原文的编码和换行信息。保存携带基础版本和幂等标识。并行编辑发生冲突时保留草稿，同一请求在超时后可安全重放。文档保存、内容解析和索引就绪分别报告。解析和索引绑定具体版本，旧任务完成后不能覆盖新版本，空版本索引就绪后当前检索也不会命中旧内容。
- Wiki 页面身份由仓库快照、文档类型和页面标识确定。业务和技术视角可保留同名页面。正文修订独立于源码快照，每次编辑或恢复旧正文均追加新修订。人工编辑和审批应用都检查权限及基础修订。Agent 对 Wiki 的改动保存为可比较、应用或丢弃的草案。经明确授权的空间文件生成或编辑沿用普通版本写入规则，产物卡片引用实际写入的版本。异步索引和导出更新跟随生效修订。
- Wiki、源码和图谱间的引用固定同一仓库快照。版本缺失或不可读取时如实报告。源码预览和结构化文档解析应给出稳定的行段、页码或单元格定位，并标明截断与二进制内容。导出按精确修订、格式和所选内容范围生成并缓存，生成和下载各自重新授权。缓存只登记已生成且可读取的产物，渲染失败或取消后可重试。首批可沿用 Markdown，版式文档、只读 PDF 解析和结构化文件编辑在对应格式有保真验收后开放。

## 取舍

追加版本比直接覆盖当前正文需要更多存储，还要处理失效索引与清理竞态。稳定引用允许审计、回看、冲突恢复和重新导出。首轮实现可用现有本地数据库与受管文件目录，分开记录文件落盘与元数据提交，使失败可以补偿。已有项目与 Wiki 版本继续按原身份读取，只有确实保留源快照的新引用才承诺精确版本定位。

## 验收场景

- 同一仓库关联两个空间后解除其中一个关联，搜索和导航立即撤出受影响范围，另一个空间与独立仓库入口仍按现有权利可读。归档空间拒绝写入，降低配额保留既有资料。
- 并发保存同一基础版本时只有一次成功，超时重试返回原版本。空文档和长文均可按原文回看，晚到的解析或删除任务不改变当前版本或恢复后的文件。
- 旧快照中的同名页面按文档类型分别打开并准确回到源码。草案审批遇到编辑冲突或撤权时拒绝应用，历史与导出仍可按各自授权的精确修订读取。
- 同目录上传冲突、原目录不存在和永久清理失败分别可解释。导出仅在产物实际完成后提供下载，失败重试后仍对应原修订与内容范围。

## Wiki 生成附件

从 Wiki 修订下的「修订导出」选择 Markdown、PDF 或 Word，并选择整页或单个章节。生成结果记录页面、修订、内容范围、大小和摘要。相同修订和范围的重复请求使用已完成的文件。生成与下载会各自校验权限，快照退役期间文件暂停访问。

Markdown 导出保留原文。PDF 呈现标题、列表、代码行和原修订标识。PDF 输入上限为 192 KiB，输出最多 180 页及 16 MiB。超出此范围的正文可按章节导出或下载完整 Markdown。

Word 导出保留可编辑的标题、段落、列表布局、代码行和原修订标识。含东亚文字时嵌入项目附带的字体。输入上限为 192 KiB 和 10,000 行，输出上限为 12 MiB。已用 LibreOffice 渲染检查合成的多页中文文档，并核对了缓存回读和备份恢复后的下载字节。[Office Open XML 规范](https://ecma-international.org/publications-and-standards/standards/ecma-376/)、[字体部分](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/ea097c57-5794-4624-b08e-017b47051b1d)。

## 空间 PDF

空间里的「导入文档」支持 PDF。编辑者可创建 PDF 文档或上传新修订。每个修订按原文件字节计入配额，可原样下载，也可恢复到新的修订。空间读取、搜索和问答按具体版本显示页码。只读预览使用提取出的逐页文字，标注截断及没有可提取文字的页面。扫描件保留原件供查看，全文检索取决于原件是否带文字层。

上传按空间单文件限制及全局 2 MiB 请求上限校验，最多处理 180 页。解析使用有时限的子进程。密码保护或无法解析的文件会返回明确状态。原件、逐页索引和版本回执一并提交。Markdown 编辑、模型生成与 PDF 的追加修订各自执行格式和基础版本检查。[PDF.js API 文档](https://mozilla.github.io/pdf.js/api/)。

HTTP 客户端使用 `Content-Type: application/pdf` 和 `Idempotency-Key`。新建调用 `POST /api/v1/spaces/{spaceId}/documents?name=...`，可选 `parentId`。追加调用 `PUT /api/v1/spaces/{spaceId}/documents/{itemId}?baseVersionId=...`。指定版本的 `/export` 返回原文件。

## 空间 CSV

工作台可导入 UTF-8 CSV、逐格修改和导出指定修订。修改指定单元格时保留其他字段原始字节、BOM、换行和引号。编辑、上传新版及恢复均检查基础版本与幂等键。搜索及问答可定位到旧修订内从 1 开始的行和列。预览把表格内容作为原文显示。

导入与 PDF 使用相同路径，内容类型设为 `text/csv`。单元格编辑使用 `PATCH /api/v1/spaces/{spaceId}/documents/{itemId}/cells`，提交 `key`、`baseVersionId` 和 `{row,column,value}` 格式的 `edits`。服务支持 4096 行、每行 128 列和总计 20,000 个单元格，每次编辑最多 128 个单元格。[CSV 数据格式](https://www.rfc-editor.org/rfc/rfc4180.html)。

## 空间文档生成

空间编辑者可在选定目录生成新 Markdown，或用已保存的当前版本生成新修订。确认生成后，配置的模型收到指令和已保存的正文。编辑输入的正文上限为 48,000 字节。保存前再次验证空间权限、目标位置、基础版本和配额。工作台的产物卡片打开实际写入的不可变版本。

REST 的 `POST /api/v1/spaces/{spaceId}/documents/generate` 和 MCP、CLI 的 `generate_space_document` 接收目标、指令与幂等键。成功后使用相同键可重取原版本。服务中断时，结果未确认的请求会保留回执并阻止自动重复调用模型。

## 工作台管理

编辑者可移动或重命名文档和目录。文件身份和已有版本链接在移动后继续可用。导入 UTF-8 Markdown 时，可选择新建文档或给当前目录中的文档追加修订。同名新建发生冲突时，可修改名称另存，或保留已选文件并指定需要追加修订的文档。导入保留 BOM 和原始换行。

关联仓库时可选择跟随仓库或固定到已发布的知识快照。恢复关联会复核两侧权限并重新启用原来的快照范围。空间设置支持限额、成员角色和所有权移交。空间管理员可永久删除回收站条目，或从「已删除空间」恢复空间。归档空间的配置、文档和关联保持只读，管理员可执行状态变更。
