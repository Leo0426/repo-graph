# 在现有单机应用中分阶段扩展能力

现有应用已提供本地目录与归档索引、代码检索、Wiki、组织归属和辅助评审。拟在现有 TypeScript 服务内扩展领域能力，以实际行为、数据不变量和验收场景描述新能力。统一沿用本项目已有的接口、授权和持久化边界，按已发布接口的兼容约定演进。

## 决策

- 首个端到端切片覆盖源码接入、冻结仓库快照、发布可读 Wiki、通过引用打开同版本源码及图谱。用本地目录和归档验收基础链路，再接入 Git 来源。
- 后续用项目空间串联仓库与资料，再拓展有据检索、会话及客户端入口。已有的静态检查、变更评审与人工处置作为另一条演进线。组织权限随共享能力一起交付，远程执行与托管额度按运行需求引入。
- 每个切片都有服务端鉴权、持久化状态和恢复条件。工作台复用现有导航、阅读和本地化机制，按实际权限提供操作入口。深链可刷新和回访，切换身份或范围后丢弃旧响应。页面区分加载、空结果、失败、无权、部分完成以及已有可读版本。
- 原生接口与现有数据按项目自身的契约演进。内部标识、样例、模型提示、视图和集成合同在本项目中独立设计，能力以合成夹具和真实用户路径验收。

## 取舍

整套替换会同时改变索引、权限与生产入口。先在单机应用中建立版本身份和授权不变量，能让新旧入口渐进共用事实。代价是过渡期必须维护现有读取语义，并明确哪些能力已经可用。

## 验收

每个切片通过真实入口验证至少一条正常链路、一条拒绝或降级链路，以及适用的中断恢复场景。用同名仓库、同路径文件和不同版本核对导航、权限及引用。先用合成数据验证确定性契约，再单独记录实际外部服务与部署验证。
