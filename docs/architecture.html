§8 架构约束 · Architecture Constraints
🔒 repograph-core 禁止引入任何第三方依赖 领域模型层必须无外部耦合，保证可移植性
🔒 接口定义在 repograph-core，实现在子模块，禁止反向依赖 依赖方向单向，保持架构稳定
⛔ repograph-graph 不依赖 repograph-vector 图与向量是并列能力，互不知晓，防止意外耦合
🔒 CodeUnit 字段不可随意增删 影响 Qdrant payload、SQLite 缓存、图序列化的兼容性
📝 metadata 新 key 必须在 CONTEXT.md 注释说明 防止各模块各自为政，保持 payload 文档化
🔒 EXTENDS 和 IMPLEMENTS 必须分开存储 影响分析时语义不同，不可混用
🔒 禁止在 Java 类中硬编码连接地址或端口 统一从 application.properties 读取
🔒 禁止 @Autowired 字段注入，统一构造器注入 Spring 规范，便于测试，消除 Spring AOT 歧义
🔒 禁止 System.out.println，统一用 SLF4J 日志规范，生产可观测性
📦 所有依赖版本只在 gradle/libs.versions.toml 中定义 Version Catalog 统一管理，禁止在 build.gradle.kts 写裸版本号
