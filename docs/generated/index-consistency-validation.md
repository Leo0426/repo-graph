## 行为变化

| 场景 | 实现后的行为 |
|---|---|
| 文件内方法删除、改名、属性移除或文件变空 | `CodeGraph.replaceFiles` 在单个 Neo4j 事务内清除过期节点、旧出边和旧属性，再写入当前内容；成功解析的空文件也参与替换 |
| 未修改文件调用仍存在的符号 | 稳定 ID 节点原位更新，保留来自其他文件的入边；所有本轮节点写入后再解析跨文件边 |
| 增量解析失败 | 不预先删除该文件的图或向量；报告错误并保留 dirty 标记 |
| 图替换失败 | 图事务回滚，停止本轮向量写入和清理，文件保持可重试 |
| 新向量写入成功 | 按项目和文件删除不属于本轮 ID 集合的旧向量；空文件删除该文件全部向量 |
| 向量写入或清理失败 | 不提交该文件的完成指纹；Qdrant 删除异常及中断向上传播 |
| 删除后只剩孤立向量 | SQLite dirty 路径仍可枚举；重建缓存实例后能重试，不依赖图节点仍存在 |
| 项目删除中断 | 独立 `pending_project_deletions` 表保留删除状态；下次该项目删除或索引先幂等重试清理 |
| SQLite 不可用 | 未完成状态写入、路径枚举和清理完成提交显式失败；登记失败前不执行图/向量副作用 |
| 同项目索引与删除竞争 | 共用 `IndexStore.withProjectMutation` 可重入锁；等待可中断，中断后不执行回调 |
| 旧文件删除事件或排队的监听任务 | 统一防抖后扫描当前磁盘；取得锁后检查监听注册身份和关闭状态，停止/重启/关闭后旧任务失效 |
| 用户删除项目但索引清理失败 | 验证通过后先停监听；受控源码、资产注册和后续领域数据保留供显式重试，不因新文件事件自动重建 |

增量写入顺序：持久 dirty → 捕获指纹 → 解析 → 图事务替换 → 新向量写入 → 旧向量清理 →
核对源码并提交解析前指纹。任一步失败时，未完成文件仍保留 dirty；成功文件可以单独提交。
强制全量索引仍沿用先清理项目再重建的语义，因此上述“解析失败保留旧数据”针对增量索引。

接口仍位于 core，图与向量实现互不依赖。没有更改 CodeUnit 字段、metadata key 或依赖版本。
新增 SQLite 表通过 `CREATE TABLE IF NOT EXISTS` 初始化，现有 `file_cache` 结构保持兼容；空 MD5
表示 dirty，不可能与正常 MD5 摘要混淆。锁采用固定数量分片以控制内存，哈希碰撞可能串行无关项目。

## 保证范围与下一步

这是单 app 进程内的串行化和持久重试机制，不是 Neo4j/Qdrant/SQLite 分布式事务。
图事务保证图内原子替换；图成功、向量失败期间仍可能暂时不一致，查询读路径没有代际切换或 dirty 过滤。
重试由下一次该项目的索引/删除触发，没有新增定时后台清理或恢复进程自动重放。
缓存实例重建验证持久恢复，未进行真实进程 kill 的故障注入；未测量吞吐或延迟收益。

后续独立切片：

1. 异步 HTTP 索引完成后的状态/历史写入仍在 pipeline 返回后发生，需单独覆盖与项目删除的竞争，
   避免已经删除的历史被迟到的完成回调重写。这与本片防止图/向量被旧监听任务重建不同。
2. 在真实 Qdrant 上执行保留 ID 清理、项目隔离和故障恢复；增加真实进程中断注入。
3. 按既有路线建设固定人工金标、完整评估分母及阶段性能基线，再选择性能热点优化。
