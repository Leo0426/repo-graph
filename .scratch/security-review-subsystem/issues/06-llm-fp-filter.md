# 06 LLM 误报智能过滤（FR-5）

Status: needs-triage

- 类型：AFK
- 被阻塞于：01（采购工具确定后获得真实告警格式；开发期可先用 fixture 样例告警）
- 覆盖：FR-5、dev-plan P3 前半

## 要做什么

端到端交付误报智能过滤：导入源代码审计工具的告警 → 大模型结合告警上下文研判"真实漏洞 / 误报" → 输出裁决结果与理由。过滤目标明确为两类成因：代码片段孤立分析导致的误报、规则泛化导致的误报。

**注意**：本仓库 codesec-triage-agent 已建有多引擎告警导入与人工审核研判管道，开工前先评估复用其管道与裁决沉淀机制的可行性，避免重复建设；评估结论写入本 issue 评论。

## 验收标准

- [ ] 告警输入对接采购工具的导出格式（01 产出前用 fixture 定义占位格式）
- [ ] 构造标注样例告警集，包含孤立分析误报、规则泛化误报、真实漏洞三类
- [ ] 过滤结果为"裁决 + 理由"，理由能指出具体成因类型
- [ ] 在标注样例集上报告实测的过滤准确率与漏报数（不设达标线，先建立基线）
- [ ] 高性能服务器部署环境下可运行；有开关可关闭该能力

## 验证方式

对标注样例集运行过滤，人工抽检裁决理由是否成立。
