# 安全审查分系统 — 开发需求与计划(2026-10-14)

> 状态:草案。来源:装备网络安全试验安全审查分系统建设要求(用户提供的完整条款,无缺失条目)。
> 本文件为该子系统的权威需求版本,后续任务拆解与验收均以此为准。

## 1. 背景与目标

面向装备网络安全试验中的**符合性检测**与**脆弱性检测**两类要求,建设安全审查分系统,
提供自动化、多维度的安全检查能力,发现被测对象中的错误信息、安全隐患、规范性缺陷,
以及由此引发的安全缺陷和漏洞。

## 2. 建设内容(工具构成)

| 工具 | 获取方式 | 说明 |
|------|----------|------|
| 源代码审计工具 | **采购成熟商用产品** | 对应源代码/代码安全审查 |
| 软件成分分析工具(SCA) | **采购成熟商用产品** | 对应组件/成分分析 |
| 配置核查工具 | 自研(默认) | 主机配置、系统配置、安全策略核查 |
| 威胁检测工具 | 自研(默认) | 在役装备威胁检测 |

> 注:原文仅明确前两项"以采购为主",配置核查与威胁检测默认自研,如有出入在评审时确认。

## 3. 功能需求

### FR-1 多维度安全检查
对以下维度提供自动化、多维度检查:
- 代码安全、主机安全、应用安全、数据安全
- 网络架构安全、协议安全
- 安全策略、系统日志、系统配置

### FR-2 审查对象覆盖
支持针对以下对象进行审查:
- 源代码
- 二进制程序
- 安全策略
- 主机安全、应用安全、数据安全(运行态)
- 系统日志

### FR-3 在役装备威胁检测
针对在役装备进行威胁检测,至少包括:
- 是否存在被攻击历史
- 有无违规外联记录

### FR-4 漏洞智能发现(大模型,仅高性能服务器部署)
利用大模型解析代码业务逻辑,识别以下原因引发的隐蔽漏洞:
- 逻辑缺陷
- 权限设计不当
- 输入验证缺失

### FR-5 误报智能过滤(大模型,仅高性能服务器部署)
利用大模型自动判断告警是否为真实漏洞,过滤以下原因导致的误报:
- 代码片段孤立分析
- 规则泛化

## 4. 技术/合规指标(验收基线)

| 编号 | 指标 | 要求 |
|------|------|------|
| T-1 | 支持开发语言 | 至少包括 C、C++、C#、Python、Java、JavaScript、JSP、PHP(8 种) |
| T-2 | 漏洞检测类型 | 至少覆盖 OWASP TOP 10、CWE TOP 25 |
| T-3 | 编码规范检测 | 至少覆盖 GB/T 34943、GB/T 34944、GB/T 34946、GB/T 39412 |
| T-4 | 检测效率(车载平台) | ≥ 10 万行 / 15 min |

## 5. 部署形态与差异

| 部署环境 | 生效需求 |
|----------|----------|
| 高性能服务器 | FR-4、FR-5(大模型相关能力) |
| 车载平台 | T-4 性能指标;大模型能力仅在高性能服务器环境提出 |

## 6. 待确认项

1. "二进制程序审查"(FR-2)在工具清单中没有明确对应工具
   (源代码审计/SCA/配置核查/威胁检测均偏代码与运行态),
   需确认由采购产品覆盖还是需要新增二进制分析能力。
2. 配置核查工具与威胁检测工具的"自研"假设是否成立,涉及范围与工作量估计。

## 7. 开发计划(建议执行序列)

| 阶段 | 内容 | 前置 |
|------|------|------|
| P0 采购启动 | 选型并采购源代码审计工具与 SCA 工具,验证 T-1/T-2/T-3 覆盖 | 无 |
| P1 配置核查工具 | 自研 FR-1 中安全策略、系统配置、系统日志、主机安全维度的自动化核查 | 无 |
| P2 威胁检测工具 | 自研 FR-3 在役装备威胁检测(攻击历史、违规外联记录) | P1 的主机/日志数据接入 |
| P3 大模型能力 | 高性能服务器环境下实现 FR-4 漏洞智能发现、FR-5 误报智能过滤,与采购产品的告警输出对接 | P0 产出告警数据 |
| P4 车载平台适配 | 裁剪部署并验证 T-4(≥ 10 万行/15 min) | P0/P1 完成 |
| P5 验收 | 按 FR-1~FR-5 与 T-1~T-4 逐项核对,处理第 6 节待确认项的结论 | 全部 |
