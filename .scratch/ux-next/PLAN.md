# RepoGraph 下一轮体验优化计划

日期：2026-11-11。状态：八个工作包的开发、验收与双轴审查完成；已按用户确认完成本地交付，暂不推送。逐项进度与实际验证见 [实施记录](IMPLEMENTATION.md)；代码已存在不等于整个交付完成。

下一轮优先提高任务效率和信息可信度，围绕仓库、发现、研判、证据和人工审核展开。用户应能看清当前仓库、当前可做的事情、结果的证据和下一步操作。继续保留现有中性灰阶、墨绿强调、主题、导航与字号体系。

## 建议补充的五个重点

1. **可复现的预览。** 原审计出现后台进程退出 144。执行前核对启动命令、进程、日志、端口和资源版本，保证用户打开的页面对应当前构建；隔离预览的模拟 API 与真实应用分别说明。
2. **任务往返后的状态。** 除截图外，逐项验证仓库、查询、筛选、滚动、展开、图谱缩放与键盘焦点。详情关闭、语言切换、视口变化和后台轮询都不能让用户重新寻找位置。
3. **错误后的下一步。** 无数据、未授权、依赖离线、请求失败、部分完成与状态未知分别表达；错误就地给出重试或配置入口，失败保留草稿。不能把失败写成没有风险。
4. **说明的显隐有明确规则。** 可折叠的是原理、格式示例和次要解释；当前仓库、结果范围、实际任务状态、证据缺失和必要操作后果保持就地可见。帮助入口使用“输入格式”“计分口径”等具体名称。
5. **用任务收益验收。** 记录三条主路径的操作次数、错误落点及返回后状态，而非只统计 CSS 声明减少。大量数据先测量再决定是否虚拟化。

## 01 统一仓库上下文与检索范围

现行契约已采用当前仓库默认、跨仓库显式选择“全部已授权仓库”。保持 CONTEXT、交互规则、REST 参数和测试一致；不能仅按实现中的偶然行为改写约束。范围提示显示实际生效范围，跨域跳转保留仓库，离线测评继续显示自身语料与时间。

验收覆盖选择 A、切换 B、清空、刷新、前进后退、撤权和同名符号。提示、请求参数和返回范围一致；旧响应不能覆盖新仓库。全部授权范围必须在服务端排名和分页前生效，前端隐藏入口不能代替权限校验。

## 02 明确能力与依赖状态

为检索、索引、图谱、结构事实、模型辅助和审核整理一张能力与依赖表。健康页继续保留基础服务明细，任务入口解释当前受影响的能力。Embedding 和生成 Provider 分别表达；已配置、已启用、基础可达和真实生成成功不能混成一个状态。

Agent 的架构和修复卡片应明确为现有页面的导航入口。修复说明先收敛到实际支持的查看、状态跟踪等行为；自动生成修复与验证若尚未形成完整流程，另立功能任务。

验收至少覆盖 Embedding 离线但已有事实可读、生成关闭、依赖检查失败、无仓库和无权限。保留仍可使用的操作及明确恢复入口。查看页面不自动发送可能计费的模型连接测试，也不自动启动扫描或索引。

## 03 仓库行直接进入任务

仓库行的主入口已采用落点明确的“打开概览”；检索、发现、文档作为同行次级入口。执行时先同步该行的 projectId，再跳转对应面板。当前仓库使用稳定选中标记，列表后的操作区保持简化。

保留已有索引时间、规模和路径。待处理数量、风险数量或索引状态只有存在明确事实来源时才加入。长名称完整信息可通过键盘和触摸读取。

验收要求从指定仓库行一次激活就能进入目标任务，返回后保留筛选与阅读位置；切换仓库不触发后台工作。普通用户看不到未授权仓库和管理员动作。

## 04 Agent 分段阅读

准备区聚焦仓库、输入与启动；执行区聚焦当前 Run、真实步骤、结果和缺失信息；等待审核时突出当前报告及人工操作入口。使用既有 AgentRun 和 AgentStep 状态组织界面，不新增一套前端业务状态机。

将其他能力导航降为次级入口，模型设置按需展开。准备草稿与高级选项保持可恢复，用户可主动收起；后台轮询只更新状态，不切换阅读区域或抢焦点。手机优先展示当前任务、状态和主要操作。

验收覆盖准备、运行、部分完成、失败、模型未启用、等待审核和完成。两档字号都能阅读基线结论、建议与不确定性；步骤刷新保留滚动和展开状态；模型建议保持辅助标识。

## 05 连续查看结果与证据

为搜索和漏洞列表设计统一的阅读行为：桌面可在右侧阅读区连续切换记录，手机进入完整阅读视图；列表保留筛选、选中项和滚动位置。第一批只复用已有 CodeUnit、漏洞详情和证据接口。

阅读区按结论或摘要、位置、源码证据、相关操作排列。提供完整名称、可复制路径、对应行号和上下文；展示服务端已有的截断或缺失说明。键盘可切换记录、关闭并返回原位置。

验收包括长路径、重复短名、多行签名、缺少源码、证据读取失败及切换仓库。查看证据不改变漏洞状态；人工审核继续引用冻结快照，报告事实和模型建议分别呈现。

## 06 图谱操作与可读性

默认露出当前模式、目标、深度和查询，将使用频率较低的诊断类型放入明确的更多查询区域。具体常用模式顺序先通过实际任务验证，保留所有已有入口。

选中节点后突出相关节点与连线，提供查看源码和继续查询入口，保留当前视图。检查亮暗主题下的连线、选中态和标签，调整点阵背景的视觉权重。大图保留显示上限、适应画布和真实范围提示。

验收使用小图、大图、长名称和孤立节点；鼠标与键盘都能定位目标并回到源码。关联查询仍说明可达关系，不能把现有数据画成未经证实的完整调用路径。

## 07 命令面板与长列表

命令面板按最近使用、当前仓库、页面组织，空输入优先展示有用的最近项；匹配同时支持中文名、英文名和常见别名。保留只读导航与查询的边界，不加入隐式扫描、删除或生成动作。最近仓库按当前权限重新校验。

长列表先增加明确的分页、结果范围和连续阅读；为高频列表验证紧凑视图的价值。使用 20、200、1000 条虚构数据记录渲染与滚动表现，再决定是否需要虚拟化。

优先处理仓库和漏洞列表，复用搜索现有加载更多能力。明确显示当前展示范围、筛选后数量与总量口径；“紧凑”只压缩留白和次级信息，不缩小可读字号或删除状态、位置和操作。测量记录包含浏览器、视口、数据规模、首屏耗时、DOM 数量和滚动观察，同条件比较改动前后。

验收覆盖无历史、损坏缓存、失效仓库、无匹配、输入法、键盘及窄屏；结果不能暗示当前页等于整个项目。紧凑模式仍保留状态、标题、位置与可访问操作。

## 08 语言与样式维护

将账号、组织、Provider 表单与错误反馈中的硬编码中文迁入现有 i18n，保留代码符号、协议与用户输入原文。统一刷新、重试、返回和主要动作的用词。

帮助入口跟随对应字段或区块标题，使用计分口径、输入格式等具体名称，减少孤立的说明行。可访问名称包含所属对象；错误、实际范围和当前任务状态继续就地呈现。

按页头、控件、列表和阅读区整理共享 CSS，把同一组件分散的定义收拢，保留响应断点和必要作用域。每个组件独立整理与验证，不同时改布局和大批重写样式。

在现有视觉检查之外补充 SVG 连线、选中态、焦点态、菜单滚动、200% 缩放和长英文。截图差异必须人工检查；更新基线不能替代解释变化。

## 验证与交付

保留已有基线；继续实施前核对当前行为、预览版本及未解决失败，补足可重现记录。每个 PR 运行 design-system 和受影响工作流；跨面板变更运行 shell 与 workspace；完成本轮后执行全部 UI 用例。新增 HTTP 契约或权限行为时，按 VALIDATION 增加对应服务端检查。

布局检查覆盖 1440、1024 和 390px，亮暗主题、键盘和减少动态效果；长内容补查 320px 与 200% 缩放。交互检查覆盖成功、空数据、加载、失败重试、部分完成和权限不足，并保持已有请求乱序保护。

用三个连续任务验收：从仓库进入代码并查看来源；从发现进入研判并定位人工审核入口；依赖不可用时理解受影响能力并使用恢复入口。先记录当前操作次数、误入次数和返回时状态保留情况，再比较改动效果。

每个 PR 草稿提供问题、最终行为、实际验证及代表截图；外部创建与推送不属于本次已确认的交付。模拟 API 与真实服务验证分别记录。确认性能瓶颈或任务收益前，不预设性能提升数字。

最终完成还要求：打包后的资源与本轮源码一致；真实应用能够启动、登录并完成只读主路径；向用户提供可访问地址与明确版本。记录实际通过、失败、跳过和未运行项。关闭测试或预览终端后的进程存活情况需要核对，不能再把后台退出日志与“预览已起来”同时作为交付结论。

## 实施边界与待验证选择

01 已采用当前仓库默认、全部已授权仓库显式选择，并同步交互规则、请求与服务端权限约束。03 的主入口采用落点明确的“打开概览”，同行提供检索、发现和文档直接入口。06 的常用图谱模式仍需按实际任务验证；05 的阅读区先做搜索与漏洞，不扩展为新的通用数据模型。

本轮范围保留现有主题、技术栈、后端事实归属、权限和审核状态机。自动修复引擎、分析精度提升、新任务调度和大型数据基础设施分别规划。
