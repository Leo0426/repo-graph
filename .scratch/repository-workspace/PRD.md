# 仓库驱动的检索与缺陷工作台

Status: complete
Feature ID: repository-workspace
来源：用户要求实践 VibeCoding SDD/DDD，以代码仓库为起点聚合前端，聚焦检索、缺陷发现和真实技术能力验证；补充明确国内、国际、本地及企业网关模型均需支持。

## 问题与目标

当前页面按技术实现平铺，进入后缺少仓库起点与连续任务路径。已有账号、组织、归属、Provider 管理不能替代本轮的信息架构改造。
目标用户为研发和代码审查人员，管理员负责仓库接入与平台配置。
从选仓库开始，完成检索/源码定位/图谱/Wiki 理解、扫描/证据/研判/审核，并能查看独立测评证据及其限制。

## 验收范围

1. 主导航聚合为仓库、代码理解、缺陷发现、能力验证、管理五个工作域；功能页作为域内入口。默认进入仓库工作台，旧 hash/历史/快捷键仍可用。
2. 仓库列表与当前项目上下文为起点，进入检索、文档、缺陷、概览时带正确 projectId；无仓库、未选择、加载失败各有明确下一步，不自动扫描或调用付费模型。
3. 代码理解聚合语义/代码检索、源码定位、调用图和 Wiki；缺陷发现聚合静态扫描、依赖、代码质量、Agent 研判与人工审核。已有交互和授权保留。
4. 能力验证聚合真实服务状态与离线检索测评；明确服务可达、索引状态、模型连接和质量结果是不同证据。无结果不展示成功或虚构指标。
5. 管理集中账号/组织/归属/模型/审计；模型提供 DeepSeek、通义、硅基流动、OpenAI、Anthropic、Gemini、Ollama 和自定义企业网关接入模板。服务模板不是新的领域 Provider，也不是兼容性保证。
6. 核对协议差异，持久化选择并发送正确输出限制字段；保留加密、密钥不回显、编辑地址显式更换凭据、连接测试、启停和旧配置兼容。模型 ID/地址可编辑，模型价格不伪造。
7. 新页面及入口支持中英文、键盘、手机；切换项目/前进后退及失败重试不丢失或混淆上下文。
8. 新增行为测试、完整相关回归、渲染检查与本地新版运行；记录已验证/未验证边界。

## 领域与实现约束

复用 Account、Organization、ProjectOwner、projectId、CodeUnit、VulnFinding、AgentRun、ModelProvider。
导航工作域只是 UI 投影，不新增业务实体或跨存储复制状态。projectId 仍是本地根路径身份，不冒充远端 Git 仓库 ID。
已有后端事实和权限为权威；生成模型与 Embedding 独立。模型辅助结论不替代启发式/人工结论。
SDD 以本规范→行为测试→实现→验收记录落地；DDD 以现有领域边界和术语组织页面，避免额外框架或纯宣传标签。
不在本轮引入新的索引算法、SSO、多实例部署或自动远程仓库克隆；保留现有本地仓库接入方式。

## 测试决策

- 浏览器：五域导航、旧深链/历史、仓库到检索/缺陷/Wiki、无项目/失败恢复、普通权限、语言/键盘/窄屏。
- Provider：本地 HTTP 断言 token 字段、Bearer、非流式/SSE 与保存重启；模板填写不自动保存/调用，切换模板不泄漏旧 key。
- 不用模拟 API 回归证明真实厂商调用；外部凭据缺失时明确记录。部署现有 localhost:8080 供用户查看。
